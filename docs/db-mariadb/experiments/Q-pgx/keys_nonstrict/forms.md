# keys_nonstrict forms (pgx)
PG hypothesis transferred: the Postgres design relies on a partial index (`WHERE completed_at IS NULL`), INCLUDE columns, LATERAL probes and plan-cache tricks. On InnoDB/MariaDB there are no partial indexes (COMPLETED rows are in every index; `completed_at IS NULL` is a `ref_or_null`/range on the 2nd key part), no INCLUDE (covering = trailing key columns), the table is clustered on `id` (VARCHAR(255)) and every secondary entry carries it, there is no LATERAL, no extended statistics and no generic-plan flips. Portable lessons kept: no GROUP BY when an anti-join already yields one row per key, order by index order with LIMIT, `<=` conjunct before the tie-break, redundant `completed_at IS NULL`. Smoke test: all forms parse on MariaDB 12 and return the same rows as the branch SQL on a 30k-row toy table (not a performance statement).

Index names refer to the branch DDL (`idx_outbox_record_status_completed_created_id (status, completed_at, created_at, id, partition_no, next_retry_at, record_key)`, `..._key_completed_created_id (record_key, completed_at, created_at, id)`, `..._status_completed_retry (status, completed_at, next_retry_at, partition_no)`, `..._status_completed_partition (status, completed_at, partition_no)`). `FORCE/IGNORE INDEX` forms fail with error 1176 on any schema lacking the named index: HIGH RISK, measurement aid only. Baseline: branch SQL (anti-join restricted to earlier due rows of the same status).

|---|---|---|---|---|---|
| kn_leftjoin | LEFT JOIN ... IS NULL with status/due restriction in ON | "not exists" short-circuit, join order freedom. | outer status index ordered; inner key index + row filter on status/next_retry_at (needs row lookup: those columns are not in the key index). | filesort if reordered. | yes |
| kn_split | two NOT EXISTS (`<`, `= AND id <`) | pure ranges, as ks_split. | key index; status/next_retry_at filtered per row after lookup (clustered, VARCHAR(255) PK). | two probes. | yes |
| kn_head | `o.id = (first due incomplete row of the key)` via ORDER BY created_at,id LIMIT 1 | single ordered probe; scans past non-due/other-status predecessors only. | key index, then lookup for status/due filter. | S5 hot keys (2000 rows/key) with many non-due heads can scan long. | yes |
| kn_window | ROW_NUMBER over due rows of the status | one pass over due rows only (filter status, due, partition inside the derived table, so it shrinks early; partition push-down assumes key-to-partition determinism). | status index range, covering (all columns in index). | no early stop for LIMIT: bad on large backlog. | MySQL 8 |

| kn_force | base with FORCE INDEX both sides | pins plan. | as base. | HIGH RISK. | yes |
