## Hypothesis / change
Hypothesis: the key-table forms (`JSON_TABLE`, `VALUES` CTE; round 1b `pa-06`, `pa-08`) change the throughput of the polling loop under
concurrent writes (S10) relative to `IN (:recordKeys)`. Change: `pages.sql` only; no DDL, no code change in the worktree.

**Harness change (needed).** `concurrency` pollers replaced `recordKeys` with the keys of the keys query, but `recordKeysJson` /
`recordKeysRows` kept the static sample, so the two forms would have run with the wrong keys. `Params.kt` got `bindKeyForms`, called
in `Extra.kt` after the replacement; noted in `harness/README.md`. The `m5c-in` runs do not use these parameters.

- **Drift** (`m5c-in` 1 vs 4): S2 -0.1 %, S4 -2.4 %.
- **Noise:** `STATE.md` has no S10 threshold; HOT 11 % is used for latencies. S2 is bound by the producer rate (processed = inserted = 500 +
  backlog), so rec/s cannot separate the forms there. S4 spread over the four runs is 919-969 (about 5 %), below 11 %.

## Verdict
- **`m5c-json`:** S2 throughput no difference; `pages` p50 +0.16 ms (0.17 -> 0.33, outside the 11 % noise, absolute cost small, p95 +0.2 ms) = a
  per-call loss not visible in rec/s. S4 throughput no difference (-2.5 % vs run 1, within drift); pages p50 +0.1 ms (~+12 %, p95 equal). **No win.**
- **`m5c-values`:** same as json on S2 (loss in `pages` latency only). S4: +2.7 % vs run 1, +5 % vs run 4, within noise; pages p50 +0.1 ms.
  **No win** (no difference in throughput).
- **`IN` stays.** A derived key table (a code change that builds a key list/table per poll) is not worth it: with the key-table forms the
  `pages` call is not faster even under S10, and its p50 is far below the keys query (S4 about 1 ms vs 9 ms, S2 0.2-0.3 ms vs 0.4 ms), so the form cannot move S10 throughput much.

## Deviations / risks
- One pass per order slot (4 cells per label as in the spec), not the two-pass protocol; gen S2 and S4 once each.
- S10-S2 at rate 500 is saturated by the producer, so only latencies are informative there.
- `--rate 500` S4 processes more than it inserts (backlog drain), which makes absolute rec/s less stable (~5 % spread).
