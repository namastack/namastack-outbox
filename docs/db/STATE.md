## Phase 0 baseline summary (details: 01-baseline.md)
- Key query filter on, 64p: A 5.0 ms/7.4k buf, B 265 ms/106k, D 38 ms; 256p: A 19, B 367, D 141. Filter off 64/256: A 1.3/2.4, B 56/76, D 4.5/6.4.
- B: parallel seq scan + hash over all incomplete rows. D: anti join quadratic per key (358k–1.9M rows removed by join filter). partition_no never an index cond at 64p.
- findIncompleteRecordPages 10/100/1000: A 0.3/0.8/4.0, B 0.2/6.6/22, D 3.9/40/40 (sort spills).
- Writes: ~26 ms/1k inserts, ~35 ms/1k updates; WAL 2.4 kB / 3.3 kB per op (WAL more stable, ±1%; tps ±3%).
- withMaxRows invisible to planner (Execute row count only) AND disables parallelism (Workers Launched 0). Use `serial` rows for withMaxRows queries. Used by both key queries, find{Completed,Failed}Records(cutoff,limit), delete{Completed,Failed}Records id selects. Cleanup selects 157–273 ms (seq scan + spilling sort).
- plan_cache_mode=auto stayed custom in all probes; forced generic much worse (up to 872 ms B/on/256p).
- Index usage: record_key_created ~0 scans (drop candidate, 16 in D); status_retry 0–1; partition_status_retry only countRecordsByPartitions; status carries most reads (countByStatus(COMPLETED) ~1M entries, ~24 ms).
- Caveats: data dir on tmpfs (all cache hits, no I/O cost). D has only 95 due keys. C has no COMPLETED. E ≈ A. countByStatus from OutboxInstanceRegistry is on the instance table, not outbox_record; cleanup methods have no main-code callers in the library. workload-mix.sh/write-cost.sh mutate data → run last.
